# Kegare: Design (Step 1: Base Systems)

A cursed-energy combat framework for **NeoForge 21.1.x / Minecraft 1.21.1 / Java 21**, built mainly for **PvP with friends**.
Step 1 is the foundation only. There are no real techniques, mobs, domains or lore yet. Those get designed once this base is proven.

- Mod ID: `kegare` · Package: `com.cnethuka.kegare` · Build: ModDevGradle MDK
- Everything is server-authoritative. Clients send key intents and render what the server syncs.

---

## 1. Naming rule

Code uses neutral IDs (`ce`, `technique`, `domain`, `trait`). **Every player-facing name lives only in
`en_us.json`**, which is generated by `data/KegareLanguageProvider.java`. To rename a term, change the constant at
the top of that file and run `./gradlew runData`.

| Code ID | Display name (for now) |
|---|---|
| `ce` | Kegare |
| `technique` | Imprint |
| `domain` | Dominion |
| zero-ce flag | Severed |
| reroll item | Purification Talisman |

Datagen fails if any registered technique, ability or trait has no lang entry.

## 2. Data model (NeoForge data attachments)

| Attachment | Saved | Kept on death | Contents |
|---|---|---|---|
| `kegare:ce` | yes | yes | born, severed, tier, capacity (fixed), current reserve |
| `kegare:traits` | yes | yes | set of trait IDs |
| `kegare:technique` | yes | yes | technique ID, selected slot, cooldowns (ability ID → end tick + duration) |
| `kegare:roll` | yes | yes | rolls since last Legendary (pity), total rolls |
| `kegare:combat` | yes | **no** | last-combat tick, stunned-until tick (game time) |
| `kegare:cast_state` | no | no | runtime: active charge/channel, active toggles |
| `kegare:sync_state` | no | no | runtime: "needs sync" flag |

World-level: `UniqueTraitSavedData` (`data/kegare_unique_traits.dat` in the overworld) maps unique trait → bearer UUID.

All timestamps use **level game time**. They persist across restarts and are identical in every dimension.

## 3. Systems

### 3.1 ce (fixed at birth)
- **First join** rolls a tier once. Weights and bases come from config:

  | Tier | Weight | Base capacity |
  |---|---|---|
  | Zero | 2 | 0 |
  | Low | 25 | ~60 |
  | Average | 45 | ~100 |
  | High | 20 | ~150 |
  | Vast | 8 | ~250 |

  Non-zero tiers get a uniform ±`capacityVariation` (10) offset and never land on 0.
- **Capacity never changes.** Death, rerolls and items leave it alone. The only exceptions are admin debug
  (`/kegare setcapacity`, `/kegare rebirth`).
- **Reserve** (`current`) is spent by abilities and regenerates `regenPercentPerSecond` (2%) of capacity per second.
  Regen pauses for `regenPauseSeconds` (5s) after dealing or taking damage.
- **Respawn** refills the reserve to capacity.
- **Severed** = born with 0 capacity. The player gets no technique, can't reroll, and the HUD is hidden. Only the
  flag is stored; there are no physical buffs yet.

### 3.2 Traits
- A registry (`kegare:trait`) plus a per-player ID set (saved, synced, kept on death unless noted below).
- `Trait.Properties` flags:
  - `unique`: at most one bearer per world.
  - `requiresCe`: never rolled for, inherited by or granted to a Severed player.
  - `inheritable`: passes on when lost.
  - `lostOnPvpDeath`: removed when the bearer is killed by another player.
  - `birthChance`: read from config.
- Hooks: `onAdded(reason)` (BIRTH / ADMIN / INHERITED), `onRemoved(reason)` (ADMIN / REBIRTH / LOST_IN_PVP /
  RELEASED / REVOKED / CONFLICT), `onBearerKilledByPlayer`, `canRollFor`.
- **World record** (`UniqueTraitSavedData`) holds:
  - bearers
  - pending successions
  - offline revocations
  - last-seen times
- **Login reconcile:** applies revocations, drops unknown IDs, re-claims a lost claim (world record wiped), and
  strips unique traits held by someone else or in succession.
- **Release** (`/kegare trait release <trait>`, or `uniqueTraitInactiveDays`) frees a unique trait from its holder:
  - an online holder loses it immediately
  - an offline holder loses it on their next login (revocation)
  - an inheritable trait then passes on (below)
- **Succession** (`TraitSuccession`): an inheritable trait that loses its bearer becomes *pending*.
  - Birth rolls can't take a pending trait.
  - After the trait's delay, it goes to an heir chosen by `TransferRules`: online, not Severed (if it needs ce),
    not the previous bearer.
  - RANDOM picks any eligible player. KILLER picks the killer if eligible, otherwise random.
  - If nobody is eligible, the next eligible player to log in gets it.
  - Admin `trait add` overrides a pending succession.
- **`kegare:lensing_eyes`** (unique, requiresCe, inheritable, lostOnPvpDeath, 1% birth, **no gameplay effects**):
  - **Killed by another player** (direct hit, or kill credit, e.g. knocked into the void): it is stripped before
    respawn, and after `lensingEyesTransferDelaySeconds` (30) it opens in an heir per `lensingEyesTransferMode`.
    Everyone sees the anonymous broadcast *"The eyes have closed... and opened elsewhere."*
  - **Any other death:** the bearer keeps it.
  - Hidden advancements. They are **not announced in chat**, because an announcement would name the bearer or heir
    and break the anonymous broadcast. The earner still gets the toast.

    | Advancement | Frame | When |
    |---|---|---|
    | *Clear Sight* | challenge | born with it |
    | *The Cycle Continues* | challenge | inherited it |
    | *Eyes Closed* | task | lost it (PvP, release or revocation) |
    | *Blinded* | goal | killed a bearer |
| *Something's Missing* | goal | a full-detail Read of a Severed player (§3.32) |

### 3.3 Technique framework
- Registry `kegare:technique`, synced to clients so the HUD can resolve names and ability lists by ID.
- `Technique` = rarity (COMMON / RARE / EPIC / LEGENDARY), an ordered **ability list** (cycled with next/previous),
  an optional **ultimate** (the ultimate key, where domains will plug in), a test-content flag, and the hooks
  `onAssigned` / `onRemoved`.
- `Ability` interface: `cost`, `cooldownTicks`, `castType`, `upkeepPerSecond`, min/max charge, max channel,
  `canCast`, `execute`, `tick`, `onEnd`. Costs take the caster so traits can scale them later.

  | Cast type | Lifecycle (server, `CastManager`) |
  |---|---|
  | INSTANT | press → validate → pay cost → `execute` → cooldown |
  | CHARGED | press → validate (cost checked) → charge (`tick`) → release ≥ min charge → pay → `execute(charge 0..1)` → cooldown. Early release or stun cancels free |
  | CHANNELED | press → validate → pay start cost → `execute` → each tick pay upkeep/20 + `tick` → release / out of ce / max duration / stun → `onEnd` → cooldown |
  | TOGGLE | press → validate → pay activation → `execute` → each tick pay upkeep/20 + `tick` → press again / out of ce → `onEnd` → cooldown. Stuns don't end toggles |

- Shared checks in `CastManager.tryCast` / `validate`: alive, not Severed, has a technique, not busy (one
  charge/channel at a time), **not stunned**, off cooldown, can afford, plus `ability.canCast`.
- Charges, channels and toggles are runtime-only and end on death, logout and technique change.
- **TEST CONTENT** (`technique/test/`, config `[test_abilities]`):

  | Technique | Rarity | Abilities |
  |---|---|---|
  | `test_kinetic` | Common | Dash (instant), Burst (charged) |
  | `test_flux` | Rare | Hover (channeled), Aura (toggle) |
  | `test_apex` | Legendary | all four, plus Shockwave (instant ultimate) |

  Epic is deliberately empty, which exercises "skip rarities with no technique".
  Set `includeTestTechniques=false` once real techniques exist.

### 3.4 Rolls and pity
- Weighted rarity roll (Common 50 / Rare 30 / Epic 15 / Legendary 5), then a uniform pick within that rarity.
- **Never rolls into the current technique.** Rarities with no eligible technique get weight 0.
- `rollsSinceLegendary` = completed rolls since the last Legendary, so the roll in progress is number n = counter + 1.
  - **Soft pity:** n > 30 adds (n − 30) × 5 to the Legendary weight (roll 31: 10, roll 49: 100).
  - **Hard pity:** n ≥ 50 is a guaranteed Legendary.
  - **Reset** on any Legendary.
  - If the only Legendary is your current technique, pity can't fire and the counter keeps climbing.
- **First join:** roll ce, then traits, then technique (unless Severed), and award *Awakening*. Severed players
  also get *Severed*.
- **Purification Talisman:** rerolls the **technique only** (ce and traits untouched). It is refused, and not
  consumed, for Severed players and while in combat (*"You can't purify mid-fight."*). It awards *Reawakening*.
- **Roll reasons** (`RollReason`, `PityState`):

  | Reason | Counts toward pity | Reawakening |
  |---|---|---|
  | BIRTH | yes | no |
  | TALISMAN | yes | yes |
  | ADMIN (`/kegare reroll`) | yes | no |
  | REPLACEMENT | **no** | no |

  REPLACEMENT is the free roll on login when a player's stored technique no longer exists (removed by an update).
  It rolls on base weights (no soft or hard pity), leaves the pity counter and roll total untouched, and tells the
  player *"Your Imprint was removed by an update and has been re-rolled."*
- Any Legendary awards *Chosen by Fate* (challenge frame); a hard-pity Legendary also awards *Bitter Luck*.
- All advancements use `minecraft:impossible` and are granted from code (`KegareAdvancements.award`).
- The pity math is plain Java (`PityRoller`, `CeRoller`) and unit-tested (`./gradlew test`).

### 3.5 Input and networking
- Keys: cast **R**, next **Z**, previous **X**, ultimate **V** (rebindable).
- C→S `IntentPayload`: only *which key went down or up* (`CastIntent`). The server resolves everything else.
- S→C `SyncPayload` (owner only): ce, capacity, tier, severed, technique, selected slot, cooldowns, active toggles,
  current charge/channel, traits. It is sent at most once per tick, and only when something visible changed
  (ce syncs when its whole number changes). The client counts down cooldowns locally from game time.
- Network version `1`. Bump it when payload formats change; mismatched clients are refused.

### 3.6 HUD
- A registered GUI layer (`kegare:ce_hud`, top-left, offset in client config) shows:
  - the technique name, in rarity color
  - the ce bar with current/capacity
  - ability slots: every slot on cooldown dims, shows a sweep for the remaining time and its seconds left;
    the selected slot is highlighted, and active toggles and casts get outlines
  - the ultimate slot, labelled with its bound key
  - the selected ability with its cast type and cooldown
  - a charge or channel progress bar
- Hidden for Severed players, when F1 hides the GUI, on the F3 screen, and in spectator mode.

### 3.7 Combat state (`CombatHelper`)
- `markCombat`, `isInCombat` (`combatTagSeconds`, 10s), and `isRegenPaused`.
- `stun(entity, ticks)` never shortens an existing stun and interrupts a charge or channel. `isStunned` is
  respected by every cast. Use `stunTicksRemaining` and `clearStun` to inspect or reset it.
- Players are tagged on dealing or taking real damage (`LivingDamageEvent.Post`). The API works on any
  `LivingEntity` for future systems.

### 3.8 Debug commands (op level 2)
`/kegare info [player]` · `setce <player> <amount>` · `setcapacity <player> <n>` · `settechnique <player> <id>` ·
`reroll <player>` · `setpity <player> <n>` · `trait add|remove <player> <id>` · `trait release <id>` (frees a
unique trait from an online or offline holder) · `trait status <id>` (holder / passing on / waiting) ·
`rebirth <player>` · `stun <player> <seconds>` (extra, for testing stun; 0 clears).
ce is always shown as whole numbers (floored, like the HUD); the stored value keeps its fraction.

### 3.9 Config
- **Server TOML** (`config/kegare-server.toml`, where NeoForge 21.1 keeps server configs; synced to clients and
  hot-reloaded when edited) holds **every balance number**.
  Sections: `ce` (with `tiers`), `traits`, `roll` (with `weights`), `combat`, `test_abilities`.
  The `traits` section includes:
  - `lensingEyesBirthChance`
  - `lensingEyesTransferMode` (RANDOM | KILLER)
  - `lensingEyesTransferDelaySeconds` (30)
  - `uniqueTraitInactiveDays` (0 = off; fractions allowed)
- **Client TOML:** HUD on/off and offset only.
- Both are editable in-game via Mods → Kegare → Config. Labels are generated into the lang file.

### 3.10 Data generation and art
- `./gradlew runData` generates lang, the item model, tags (`kegare:talismans`), the talisman recipe
  (gold + amethyst + paper; overridable by datapack) and the advancements.
- `python3 tools/gen_placeholders.py` regenerates the 16×16 placeholder PNGs (talisman, ce bar, ability slots).

## 4. Extension points (how later content plugs in)

- **New technique:** create a `DeferredRegister<Technique>` on `KegareRegistries.TECHNIQUE_KEY`, build abilities
  with `BaseAbility`, add the lang names, and put the numbers in config. Nothing in the base changes.
- **New trait:** register a `Trait` subclass (unique or not) and override its hooks.
- **Domains:** a technique's `ultimate` ability. It uses `CombatHelper` (stun, combat) and the shared
  `CastManager.validate` checks. Domain-specific state gets its own attachment.
- **Cost or cooldown modifiers** (e.g. from traits): `Ability.cost(player)` and `cooldownTicks(player)` already
  receive the caster.
